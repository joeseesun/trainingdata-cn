《谷歌杰夫·迪恩：AI 初级工程师一年内上岗，前沿大模型只剩几家》

2014 年，杰夫·迪恩和同事把一篇论文投给 NeurIPS，被拒了，理由是这项技术不太可能有影响力。

那篇论文讲的是蒸馏，把大模型的能力压进小模型。十一年后，DeepSeek 靠类似的技术路线把训练成本打下来，全行业跟进。今年 5 月，红杉资本播客 Training Data 在现场录了一期节目，对谈嘉宾比尔·考夫兰把这段旧账当面翻出来，杰夫在台上笑，台下一屋子听众也笑。

杰夫·迪恩现在的头衔是 Alphabet 首席科学家。MapReduce、BigTable、TensorFlow，谷歌二十多年的技术底座他几乎都碰过，BERT 论文的作者名单里也有他。采访他的比尔·考夫兰是红杉合伙人，加入红杉前在谷歌管了近十年工程，俩人到现在还偶尔约晚饭。

这场对谈从 2012 年的 1.6 万个 CPU 核，一路聊到 AI 初级工程师什么时候上岗，中间还夹着诺贝尔奖、皮焦耳和 50 个虚拟实习生。挑重点说。

十三年前，他用 1.6 万个 CPU 核赌对了 scaling

很多人觉得 AI 是这三四年才火起来的，杰夫把起点拨回到 2012、2013 年。那时候研究者发现，同一套神经网络方法，视觉能用，语音能用，语言也能用，机器学习就此甩开了手工特征的老路子。

2012 年谷歌内部关心一个问题：怎么把神经网络训得特别大？他们真训了一个，规模是当时已知最大网络的 60 倍，动用 1.6 万个 CPU 核，因为数据中心里现成的就这些。结果非常好。

从那以后谷歌内部有句口诀：模型更大，数据更多，效果更好。这句话在过去十二三年里基本一直成立。

这批实验让谷歌内部确信，堆规模这条路走得通。后来启动 TPU、押注 Gemini，源头都是这个判断。

现在杰夫给这条曲线加了三个新变量。算法改进让同样的算力训出更强的模型；硬件一代比一代强，单芯片算力持续上涨；强化学习和后训练把模型行为往人想要的方向掰。三股力量叠在一起，模型能力逐年爬坡。

他还点了多模态的名：往模型里塞音频、视频、图片、文字、代码，输出也能是这些东西，这种通用性本身就能打开一堆新任务。

他没把话说满：模型解决不了所有问题，但每年能解决的问题集合都在变大。

前沿大模型不会超过 50 家，可能一只手数得过来

比尔问了个所有人都关心的问题：大模型这张牌桌上，最后剩几家？

杰夫回答得很干脆：做绝对前沿的模型需要巨额投入，不会有 50 家，可能一只手就数得过来。这些通用模型会活得很好，同时市场上还会有大量形状各异的模型，各自专注不同的事。

把这两类玩家连起来的技术，就是开头那篇被拒的蒸馏论文。有了强模型，就能蒸馏出轻量、快速的小模型，塞进各种场景。比尔当场补刀：听说这项技术后来帮了 DeepSeek 不少忙。台下笑成一片。

这事还有个隐藏教训。2014 年的审稿人看不上蒸馏，十一年后它成了行业标配。判断一项技术的价值，时间尺度得比审稿周期长得多。

Agent 是不是期货？机器人还差临门一脚

比尔说话直，当场说行业追捧的 agent 有几分像期货，抱歉啊各位，我这个人有点直。台下笑。杰夫没接梗，给了个工程师式的回答。

他认为 agent 的路是通的：用强化学习训练，让 agent 在虚拟电脑环境里积累经验。人今天在这个环境里能干的事，agent 以后大多也能干。现在它们能做一些事，做不了大部分事，但提升路径清楚，早期产品已经对人有用。

物理机器人他给的时间表更具体。现在机器人在乱糟糟的真实房间里还干不了活，但未来一两年，会出现能在一个房间里干 20 件有用的事的机器人。这类产品会先上市，然后靠积累的经验继续学，再把成本压到十分之一，能干 1000 件事。成本工程和能力提升会咬合着往前滚。

这个逻辑链值得记住：先能干 20 件事，就有产品；有产品，就有数据和钱；有数据和钱，就能干 1000 件事。

比尔听完也松了口：看来是真要来了，虽然对我来说它现在还是期货。

诺贝尔奖、30 万倍加速和 1 万倍的算力旋钮

硬件环节，杰夫讲了 TPU 的来历。2013 年他牵头启动这个项目，当时谷歌内部的推理需求已经压不住了，专用芯片在他看来是显然的选择。第一代 TPU 只做推理，第二代开始训练推理都做。最新一代叫 Ironwood，马上发布，前一代叫 Trillium。他吐槽谷歌不知为何不再给 TPU 编号了，挺烦。比尔调侃这命名像英特尔的老路子，效果可不怎么好。

杰夫对专用硬件的判断一句话就能说清：你要的是低精度线性代数加速器，一代比一代强，再用超高速网络把成千上万片连起来，把模型计算摊到尽量多的设备上。

现场有物理学家说，辛顿拿诺贝尔物理学奖，他们这些搞物理的有点难以接受，AI 到底会走多远。杰夫说，会走得非常远。他的同事德米斯·哈萨比斯和约翰·江珀也拿了诺贝尔化学奖，谷歌连着两天办了双诺贝尔庆祝会。AI 的核心能力是从有意思的数据里学东西、找关联，这恰好是很多学科的本职工作。

他给了一个具体例子。很多学科都有极昂贵的数值模拟器，天气预报、流体力学、量子化学都是。办法是把模拟器当成神经网络的训练数据，训出一个逼近模拟器的新模型，速度快 30 万倍。这一下就改了科研流程，原来要跑一年的计算，现在去吃顿午饭的工夫能筛 1000 万个分子。

有人问推理硬件的未来是不是模拟计算。杰夫说有可能，模拟电路省电，这点很有吸引力，但数字电路更好伺候，数字推理硬件也还有很大的专用化空间。他真正关心的是另一个数字：推理硬件的效率能不能比现在高 10 倍、20 倍、50 倍、1000 倍？他觉得完全做得到，而且他本人正在花时间做这件事。

有人吐槽 TPU 不好用，CUDA 生态更顺手，还问杰夫是不是收到了很多愤怒邮件。杰夫承认体验有改进空间，然后讲了 Pathways。这个 2018 年启动的系统把底层几万个芯片抽象成一个虚拟设备池，虚拟设备到物理设备的映射由运行时统一管理，同时支持 PyTorch 和 JAX。谷歌内部用 JAX，一个 Python 进程看起来就挂着 1 万个设备，先用 4 个、8 个、64 个设备调试，改一个常数，就能切到 1000 个、1 万个芯片上跑。谷歌最大的 Gemini 模型，就是一个 Python 进程驱动几万块芯片训出来的。以前这套只给内部用，今年 Cloud Next 上宣布向云客户开放。杰夫的原话：管理 64 个处理器去伺候 256 块芯片，图什么呢。

还有开发者现场抱怨 Gemini API 的凭证体系太麻烦，希望跟 Google Cloud 的账号体系统一。杰夫说这是已知问题，开发者团队的洛根他们在处理，谷歌希望用自家模型是无摩擦的。

比尔补了个观察：传统算法分析只数操作次数，现在大家重新发现，网络带宽和内存带宽才是真瓶颈。杰夫想起研究生时代的室友，论文写的就是缓存感知算法，因为大 O 记号根本不管有的操作比别的贵 100 倍。他给了个更现代的数字：ML 芯片里把数据从 SRAM 搬进累加器花的能量，比运算本身高得多，单位是皮焦耳。现在做系统的人，得把皮焦耳挂在嘴边。

聊到计算基础设施的未来，杰夫说过去五年十年，计算机要干的活已经彻底变了样。摩尔定律和登纳德缩放都停了，但 AI 要的计算完全不同。训练和推理是两种负载，值得分开优化。手机上要跑参数很多的好模型，机器人、自动驾驶要跑，数据中心更要大规模跑。然后是那个新旋钮：推理时算力。有的问题值得多花 1 万倍算力，有的不值得。这个旋钮能让模型做到 1 倍算力下做不到的事，但不能什么问题都开 1 万倍。硬件、系统软件、模型和算法技巧、蒸馏，配合起来才能让好模型跑进小算力足迹。

AI 初级工程师，一年左右上岗

观众提问环节，有人问了全场最想问的问题：全天候运转、达到初级工程师水平的 AI，还有多远？

杰夫的回答就三个词：没那么远。

比尔追问，六周还是六年？杰夫说：

「AI 这行，一年大概顶狗年的七年。我认为一年左右是可能的。」

这句话的信息量在于，他给的时间既没有十年，也没有五年。

有人追问，除了代码生成，还需要什么？工具使用，还是任务规划？杰夫没有押注某个单点技术，他给的是一条学习路径。光会在 IDE 里写代码不够，这个虚拟工程师得会跑测试，会调试性能问题。人类工程师怎么学这些？读文档，用工具，听前辈指点。而虚拟工程师恰好擅长读文档，擅长在虚拟环境里反复试错。这两件事正是它学习的主通道，所以这条路能走很远。

杰夫自己也在 vibe coding，原话是效果出奇地好。他在 200 个聊天室里，早上刷牙能收到 9 条通知，因为伦敦的同事在另一个时区干活。有个内部演示让他印象很深：喂一个 YouTube 教育视频，提示词就一句，请做一个用图形和交互讲清这个视频概念的教育游戏。不是每次都成，但 30% 的概率能得到一个讲微分方程、火星旅行或者细胞生物学的像样小游戏。他觉得这对教育是个了不得的信号，未来几年的工具真的有机会在很多正面方向上改变世界。

终局：怎么管 50 个虚拟实习生

有人问这场军备竞赛的终局，是不是谁支票写得最大、集群堆得最大谁就赢。

杰夫的答案分两层。算法和系统一样重要，缺一不可。从 Gemini 一代到另一代，算法改进的贡献跟硬件改进持平，甚至更大。赢家得同时把两件事做到顶尖。

产品层面，他觉得大家还没找到那个几十亿人每天用的形态。可能是教育，可能是搜索式但吃透多模态优势的信息获取，也可能是帮人在工作环境里把事办成。有人顺势问，Chrome 手握分发、支付凭证和登录状态，为什么不把 Gemini 直接塞进去？杰夫说，让模型观察你在浏览器和桌面上干什么，对标签页做 OCR 或者直接读原始内容，会非常有用，谷歌有 Mariner 这类早期演示，后续怎么产品化，还没有答案。

他举了个很具体的画面：

「我怎么管理 50 个虚拟实习生？它们大部分时间做得对，偶尔需要找我拍板，我得给它们一点方向。这会很复杂。」

模型架构上，他一直是稀疏模型的信徒。人脑只有 20 瓦，靠的就是各部分各管一摊：担心身后倒车的垃圾车时，莎士比亚诗歌那部分不会激活。谷歌早期做过 2048 个专家的混合专家模型，同样的训练算力换来的模型质量提升了 10 到 100 倍。

这套早期工作证明了稀疏的价值，但他觉得整个行业还没把稀疏的空间探索透。现在的稀疏太规整。他想要的系统里，有的路径比别的贵 100 到 1000 倍，有的专家只花一点点算力，有的花很多，结构还可以各不相同。模型能随时长出新参数，也能把某一块蒸馏压缩到四分之一大小，后台再有个类似垃圾回收的机制，把省出来的内存挪去更值钱的地方。那才是一个有机的持续学习系统。

难点他也说了：现在这套方法太有效了，推倒重来很难下决心。

明天就能用的三件事

整场听下来，给三个马上能用的结论。

  • 把蒸馏写进技术选型清单。前沿模型只会剩几家，轻量模型会遍地都是。能用小模型解决的事，别硬上旗舰，成本差一个数量级，响应还更快。
  • 给 agent 的耐心定在两年，别定在两个月。杰夫的判断是路径清晰但能力还在爬坡。现在就把团队里重复性强的电脑工作整理成 agent 能接手的流程，等能力跃迁到来时你是熟手。
  • 重新分配你的算力。推理时算力是个新旋钮，把 1 万倍算力留给真正难的问题，简单问题交给蒸馏出来的小模型。开发者还可以盯着 Pathways 的开放进度，小集群调试、大集群生产，中间只差改一个常数。

最后用杰夫聊教育时的话收尾。他说，未来几年我们手里的工具，真的有机会在很多正面方向上改变世界，大家都该记住，这就是该努力的方向。这话从一个 2012 年就用 1.6 万个 CPU 核训神经网络的人嘴里说出来，分量不一样。
