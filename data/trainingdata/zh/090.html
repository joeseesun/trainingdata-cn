一天150个PR，模型包办全部代码：Claude Code之父谈编程的印刷机时刻

录制这期节目前一周，鲍里斯·切尔尼刚创下一项个人纪录：一天提交150个PR。

他是 Anthropic 工程师，Claude Code 的创造者。日常状态是每天几十个PR，全部出自模型之手。过去一年，他没亲手写过一行代码。

这是红杉资本播客 Training Data 五月初的一期，主持人是红杉团队的劳伦·里德，台下坐满创业者和工程师。开场先举手：谁在用 Claude Code？一大片。谁得了「Claude Code 综合征」？切尔尼笑着承认，他的团队平时就这么形容他。

他还顺手做了个使用调查：多数人用命令行，一部分用桌面端，用 VS Code 和 JetBrains 插件的反而不多。他自己呢？「我最近基本都在 iOS 上干活。」一个以写代码为生的人，主要工作界面是手机，这条线索贯穿了整场对话。

多介绍两句这个人。典型的工程师里的工程师，写过 TypeScript 教材《Programming TypeScript》，职业生涯大部分时间都在亲手写代码。主持人还翻出一段陈年旧事：他中学时写过一篇教程，教人用 BASIC 给 TI-83 Plus 图形计算器编程，至今还挂在网上。切尔尼赶紧说，太丢人了，千万别去搜。主持人补刀：我们肯定会搜的。

一个为「下一个模型」准备的产品

Claude Code 的诞生挺偶然。2024年底，切尔尼加入 Anthropic 内部一个叫 Anthropic Labs 的小团队，统共几个人，定位是创新孵化器。这个团队先后交出三样东西：Claude Code、MCP 协议（Model Context Protocol）、桌面端应用。任务完成后解散，最近又重组，进入第二轮，带队的是 Instagram 联合创始人、Anthropic 首席产品官迈克·克里格。

为什么选编程切入？他用了内部常挂嘴边的一个词：产品悬空（product overhang）。模型已经能做到很多事，但没有任何产品接得住这些能力。发动机已经造好了，市面上跑的还全是马车。

Anthropic 自己的路线一直很聚焦，用他的话说，公司只在意四件事：商业、企业客户、安全、编程。做一个编程产品，跟公司战略是咬合的。

2024年底，编程工具的最好水平是什么？是补全。打开编辑器，按 Tab，模型帮你补完一行代码。这是 Sonnet 3.5 第一次带来的体验。团队的判断是，模型已经准备好往前迈一大步了，别一行一行补了，直接让 Agent 把代码全写了。

于是他动手做。然后，连续六个月，这东西基本不可用，勉强能跑，他自己也只拿它写大概10%的代码。

发布之后，一开始也没火。有人用，但没有后来那种指数级增长。转折点他记得很清楚：Opus 4 发布，2025年5月。从那天起增长曲线开始翘，之后每个新模型发布都再翘一次，4.5、4.6、4.7，一路到现在。

这背后是一种很反常识的产品方法论。团队从一开始就知道，这产品六个月内不会有 PMF，因为它是为下一个模型建的。模型还没到位就先把产品做出来，赌它到位。事后看，这个赌赢了。

「编程已经解决了」

切尔尼公开说过一句话：编程已经解决了（coding is solved）。主持人请他展开讲讲。

他先反手给现场做了个调查：谁100%手写代码？有人举手。谁100%用 Agent 写？也有人举手。谁在中间？大多数人。所以按现场口径，编程算是解决了50%。

对他自己，是100%。

Claude Code 的代码库泄露过，没什么秘密：就是 TypeScript 加 React，结构很简单。选这两个东西的原因很实际，当时模型不够聪明，得喂给它「见得多」的材料，也就是待在分布内（on distribution）。就像给刚入职的熟手派活，先用他最顺手的那套工具。现在模型强了，没见过的语言和框架也能现学，但2024年底那会儿，技术选型就是生死线。

大概2025年10月、11月起，模型包办了他100%的代码。他每天提交几十个PR，前一周冲到一天150个，纯粹是想试试极限在哪。

「也有很大的代码库、很怪的语言，模型还搞不定。但通常的答案就是等下一个模型。」

有人追问：Claude Code 的成功，模型占几成，产品占几成？他说一年前大概是五五开。理由很朴素，他早年是 YC 孵化公司的第一名员工，做过好几个项目，YC 反复灌输一句话，做人们热爱的东西。模型再强，最后还是得有一个让人整天用着舒服的产品，团队在细节上抠得很狠。

两年后呢？「兄弟，我们只做一周以内的规划。」全场笑。

但他给了一个方向性判断：模型越强，外壳（harness）越不重要。今天 Claude Code 里围绕提示词注入的防御、命令的静态校验、权限模式、人工确认环节，一年后都会退居次要，因为模型自己就会做对的事。

几百个Agent，几十个Loop

切尔尼六个月前在 Twitter 上晒过自己的开发环境，发出去才发现大家觉得震惊，他自己纳闷，「那不就是我一直的写法吗」。现在又升级了：大部分工作在手机上完成，像刷消息流一样管理手头的活。

他现场演示：Claude App 左侧有个 code 标签页，点开是一排会话，通常挂着5到10个，每个会话里再跑一批 Agent。粗算下来，此刻大概有几百个 Agent 在给他干活，每天夜里还有几千个在跑更重的任务。

管理这套东西的核心，是一个叫 loop 的命令。原理简单到不像话：让 Claude 用 cron 给自己安排定时任务，每分钟、每五分钟、每天一次，随你定。相当于雇了一个不睡觉的值班工程师，专门替你守着流水线。他现在常年挂着几十个 loop：

  • 一个盯着他的PR，自动修 CI（持续集成）、自动 rebase；
  • 一个维护 CI 健康，发现不稳定的测试就去修；
  • 一个每30分钟抓一次 Twitter 上的用户反馈，自动聚类给他看。

他的判断是，loop 这种形态就是未来。团队还上线了 routines，同样的事搬到服务器上跑，合上笔记本也照常运转。

有个细节单独拎出来说。有人问，多 Agent 并行是不是得靠用户自己判断什么时候该开10个子 Agent。切尔尼说，产品层面这就是提示词的事，但更好的信号是模型自己会了：4.7 已经会主动开 loop，他让模型拉一个数据查询，模型发现数据随时间变化，就自己起了一个 loop，说每30分钟给你一份报告，接着用 Slack 的 MCP 把报告发过来。

如果用户还得琢磨怎么把工具用明白，那是产品设计没做好，不怪用户。

聊到团队的未来，他先自嘲了一句：「预测这事很难，但我坐在这儿就是来预测的。」他的判断是，通才会越来越多，而且是从工程跨到设计、产品、数据科学的跨学科通才。证据就在他自己团队里：工程经理、产品经理、设计师、数据科学家、财务、用户研究员，每个人都在写代码。各有专长，但代码成了所有人的通用技能。

SaaS 大灭绝，与还站得住的护城河

现场有人抛出那个绕不开的问题：AI 让写代码便宜10倍到100倍，SaaS 会不会迎来大灭绝（Saspocalypse）？

切尔尼说这是他最喜欢的问题，然后给了两个判断，都跟主流论调不太一样。

第一个判断借用了播客 Acquired 的常用框架，出自汉密尔顿·赫尔默的《7 Powers》，把商业护城河归成七种。他前阵子刚跟 Acquired 团队录过节目，自称见到了偶像。AI 会让这七种护城河重新洗牌，一些贬值，一些更值钱。

贬值的两种。切换成本：模型能帮你把数据和工作流从一个产品搬到另一个产品，搬家不再疼了。流程优势：Claude 越来越擅长摸清流程，尤其4.7，给它一个目标，它能像爬山一样不断迭代直到做完，「我觉得这是第一个能做到这点的模型」。比如给它一个性能指标，让它反复跑基准、改代码、再跑，直到达标。靠工作流和流程壁垒吃饭的公司，要小心了。

还站得住的：网络效应、规模经济、独占资源。这些跟 AI 关系不大，照旧有效。

第二个判断：未来十年，小团队掀翻大公司的案例会增加10倍。大公司要用 AI，得改造业务流程、重新培训所有人、扛住内部阻力；创业公司从第一行代码起就是 AI 原生的，没有这些包袱，小团队也能做出大公司量级的东西，正面硬刚。

他的结论：现在是创业最好的时候，颠覆要多到来了。

印刷机时刻

有人问，写软件会不会变成一个像会用 Office 一样的通用技能。切尔尼连说三个 yes，然后说，比那还要彻底，会像「会发短信」一样平常。

他平时只读两类书，科幻和科技史。科技史里有一个和当下最像的时刻：15世纪欧洲的印刷机。

印刷机出现前，欧洲大约10%的人口识字。这批人受雇于国王和领主，很多领主自己反而不识字，识字是少数人的职业。印刷机发明，然后有了第二台、第三台。

「印刷机出现后的50年里，欧洲出版的文献比之前一千年的总和还多。同期，一本书的价格降了大约100倍。」

识字率没有立刻起飞。学会读写需要教育体系，需要政府投入，需要有人从农田里解放出来，这个过程花了几百年，全球识字率才升到大约70%。今天人人读写，不需要文凭，职业作家这个行当也依然存在。

切尔尼认为，软件正在走同一条路，而且会快得多，用不了50年。写软件会彻底平民化，谁都可以做。会写代码的人不会消失，就像职业作家今天还在。变化的地方在于，「写代码」从一门职业手艺，变成人人都会的基本功。

推论很扎心：做会计软件，最好的人选可能是一个真正懂会计的人，工程师反而排不上号。域知识是难的，编码是容易的那部分。

Anthropic 真正领先的东西

有人问，你们内部用最好的模型，跟外面的差距是三个月还是六个月？

切尔尼的答案分两层。模型层面，没有差距。Anthropic 内部用的就是外面所有人用的模型，自己先吃自己的狗粮是铁律，团队写代码主要靠 Opus 4.7，偶尔试用一点内部代号为 Mythos 的未发布模型。

真正的差距在组织。他描述了 Anthropic 内部的日常：公司里所有事都用 Claude，他的 Claude 们整天在跑，一边写代码，一边通过 Slack 跟别人的 Claude 通信，互相搞清楚不确定的事。公司里已经没有任何手写的代码，连所有 SQL 都是模型写的。

技术对所有人开放，领先的是组织结构和流程，而这套东西可以学。他希望多出来讲讲，让外面的人也跟着进化。主持人接了一句：这恰好是创业公司的机会，组织流程从零建起，没有历史包袱。

剩下几个快问快答，信息量也不小。

本地模型还是云端模型？他说这个问题两三年后就不重要了。模型自己会决定用什么算力、怎么搭环境、什么时候起 Agent，这些不再出现在工程师的决策清单里。

知识工作的工具怎么接入？答案还是 MCP，接上 Salesforce、Google Docs、Google Calendar，Claude 面向知识工作的产品 Cowork、CLI、Claude Code 全都能用。没有 MCP 的系统用 computer use 兜底，他顺带说 Anthropic 在这块目前领先，速度慢，但4.7已经做得相当好。反正模型眼里什么接口都一样，都是 token。

现在做什么产品，能吃到六个月后的模型红利？他点了三个：Claude Design，今天已经不错，后面会好很多；围绕大规模并行的 loop 和 batch；还有 computer use。

最后，把能带走的东西列一下，都是明天就能动手的。

  • 今晚给 Claude Code 挂一个 loop：盯PR、修 CI、每半小时汇总用户反馈，任选一件开始。怕合上电脑就断线，用 routines。
  • 选型时优先模型「见得多」的技术栈，TypeScript、React 这类，产出质量立竿见影。冷门框架等模型更强再碰。
  • 用《7 Powers》盘一遍自己的产品：切换成本和流程壁垒在贬值，网络效应、规模经济、独占资源还在，资源往后者倾斜。
  • 把 Claude Code 推给团队里不写代码的人，设计师、财务、运营。域知识比编码稀缺，印刷机那段类比已经说透了。
  • 做产品别只围着当前模型优化，为六个月后的模型设计。Claude Code 自己就是这么活过来的：先做出来，等模型追上。
