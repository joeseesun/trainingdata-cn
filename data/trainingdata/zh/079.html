《Warp 创始人：终端逆袭成 AI 编程中枢，编程几年内会被「解决」》

先看一组数字。Warp 创始人 Zach Lloyd 最近上了红杉资本的播客 Training Data，主持人 Sonya Huang 请他给当下的 AI 编程能力打个分，他给了十分制的六分。同一集里，他还抛出一个更大的判断：编程会在几年内被模型「解决」，到时真正的瓶颈，是人类能不能把意图说清楚。

六分的能力，凭什么谈「解决」？这场对话里，有一家做了五年终端的公司稀里糊涂捡到的时代运气，有一段每五天进账 100 万美元却越卖越亏的定价教训，也有对这条「软件行业最卷赛道」的冷静拆解。

一个自认不擅长终端的人，做了五年终端

先介绍嘉宾。Zach Lloyd，Warp 创始人兼 CEO，公司成立五年，定位一直是帮专业开发者更快交付更好的软件。他上一段履历更响亮：Google 主任工程师（principal engineer），管过 Google Docs 的工程团队。

有意思的是，他自称终端用得不好，一直是看着身边的高手用终端干成各种事。终端在技术栈里的位置太关键，用得好的人产出惊人。但经典终端在他眼里是个糟糕的产品：难学、容易犯错、鼠标基本没用。

Warp 最初的野心是重做这个糟糕的产品。商业模式原本押在多人协作上，他拿 Postman 打比方：共享命令、共享操作手册、共享事故响应流程。这些功能后来都做出来了，而且意外有了新用途，智能体也能吃这套知识库。

创业头一年半，团队只干一件事：重做终端的输入和输出，在不削弱工具威力的前提下把门槛降下来。那还是生成式 AI 爆发之前，没人为了写代码去重新设计终端。

终端为什么在 AI 时代反而更重要了

按常理，代码都能让模型写了，终端这种上古工具该退场了。Lloyd 的答案相反：终端现在反而是和智能体协作的首选形态。理由很朴素：终端的一切都按时间组织，文本进、文本出，天然留下完整日志，多开几个智能体并行干活也很容易。

「终端成了智能体开发的中枢，这对我们来说真的是一场巨大的运气，是个巨大的机会。」

市场数据也在支持这个判断。Warp 现在有 70 万活跃开发者，在 SWE-bench 上排进前五，在 Terminal-Bench 上通常第一或第二。

更明显的是工具形态在融合。Warp 从终端长出了代码编辑器、代码评审、文件树，因为加了文件树还挨过 Twitter 用户的骂，说它不够纯粹。反过来，从 IDE 出发的 Cursor，最新版主界面越来越像聊天窗口，整体长得越来越像 Warp。Lloyd 的判断是：未来的工作台会更像终端，但严格说，它既不会是传统终端，也不会是传统 IDE。形态要跟着智能体工作流走，服务于写提示、补充上下文、审查智能体生成的 diff。

他给了两个工具一个心智模型：IDE 是代码版的 Word，终端是和电脑聊天。专业级智能体开发（他特意和 vibe coding 区分开）两个都要。手工编辑已经降级成备用界面，主界面换成了提示词。

至于为什么死磕专业开发者，他的逻辑很直接：人们每天沉浸使用的那些难做的软件，Google Docs、Spotify、Notion、Figma，都是专业者和企业造出来的。vibe coding 工具造出来的东西经济价值更低，他从来没整天用过任何一个 no-code 工具做出来的应用。

最卷的赛道，偏不打价格战

主持人 Sonya Huang 说，编程市场是她见过竞争最惨烈的软件细分领域。Lloyd 拆了一下格局：一大堆 fork VS Code 的产品，彼此长得几乎一样；另一批跑在终端里的文本应用，也彼此长得几乎一样。Warp 是唯一从终端本身长出来的平台。

差异化最明显的场景在编码之外：部署、Docker、Kubernetes、事故响应，这些终端重活让后端 DevOps 和 SRE 岗位用得很舒服。

麻烦在于对手太有钱。Anthropic、OpenAI、Google 都能用模型利润补贴自家编程工具。Lloyd 的应对分三层。第一，做高端市场，产品体验值钱，编程智能体还没沦为大宗商品。第二，主动避开最比价的用户群，比如 24 小时挂机跑原型的 vibe coder，那本来就不是专业开发者的使用模式；对专业开发者来说，整体体验贵 20、40、80 美元，和产出比是小钱。第三，押注模型路由。过去几个月 Anthropic 在前沿编程上几乎一家独大，现在 Gemini 3 和最新的 Codex 基本追平了 Claude，让用户自由选模型、按需路由到便宜的开源模型，成了应用层公司的活路。

定价这一段是全场最诚实的故事。Warp 老定价是订阅送固定 credit，比如一个月 5 万 credit，多数人只用到 2 万，按平均用量定价就能赚钱。结果用户越用越多，公司越卖越亏。当时收入增长凶猛，大约每五天新增 100 万美元（后来放缓），完全可以继续融资硬冲。Lloyd 和红杉的投资人 Andrew 反复讨论后放弃了：成本战是一场他们赢不了的比赛。

新定价改成消耗制：每月 20 美元基础费，credit 用多少买多少，用得越多公司越健康。代价是涨价引来大量用户抱怨。

「很糟心，真的。但我们实在没办法继续这样补贴下去了。」

换来的是可持续的增长。

作为应用层，Warp 手里还有一份稀缺数据：70 万开发者的终端工作流。模型选择上，70% 到 80% 的用户直接用默认 auto 档，不碰设置。auto 分高效和性能两档，混用 GPT-5.2（Codex 系）和 Sonnet 4.5。主动选模型的人里，Gemini 3 Pro 最近人气很高。总体排位 Anthropic 依然第一，Gemini 和 OpenAI 各有拥趸。Grok 至今没进 Warp，对方找过很多次，但每接入一个模型都要专门调校 harness，Lloyd 要求有明确的用户收益才做。

说到 harness，这是他眼里的真护城河：提示词怎么写、给模型什么工具、上下文怎么管。比如什么时候开子智能体、分一个独立上下文窗口，什么时候摘要，什么时候截断一条输出巨大的命令，再加上 RAG 和 MCP 的整合。这些能力全靠测量堆出来：内部 evals、公开基准，再用 Braintrust 这类平台从真实用户交互里找失败模式，回放成评测。他承认这是一次大的思维转变，但完全必要。

Terminal-Bench 的好成绩还有个独门原因：Warp 本身就是终端，能做「终端层的 computer use」，相当于浏览器自动化公司做的事，只不过发生在终端这一层。评测里有个任务是玩 Zork 那样的交互式文字游戏，别的 harness 很难处理。

明年的主战场：被系统事件叫醒的智能体

Lloyd 认为未来一年最大的变化，是智能体的启动方式。触发器从人敲提示词，变成系统事件：服务器崩溃、用户投诉聚集、安全事件告警，智能体在云端自动被唤醒干活。他管这类东西叫环境智能体（ambient agents）。

这会连带改变整个工作台的定位：从单机工具变成编排平台，一个管理自己和全团队智能体的驾驶舱。智能体会自己推 PR、给 PR 做初审、往任务系统里建卡，这些都需要追踪和协调。这是 Warp 明年最大的产品投入方向。

基建也要跟着变，Warp 正在从产品变成平台：agent SDK、智能体托管（小公司不用自己在云上搭环境，Warp 代管）、API 层（查状态、接管、看进度、读日志）、再往上是管理层（谁启动的、什么状态、产出了哪些 PR）。已经有一批创业公司专门做智能体托管，Lloyd 觉得这个品类会很有意思。

人驱动的智能体会消失吗？他的答案很克制：环境智能体先吃掉的是杂活和能一次跑完的任务，难而有趣的软件工程，还是会由人坐在工作台前完成。

关于智能体能连续干多久，他给了个具体数字：真实编码任务目前最多 20 到 30 分钟。再长就开始绕圈，上下文有限，无人值守的成本也高。效果最好的用法始终是充分引导：先和智能体一起做计划，中途定期回来检查。要跑上几小时的任务，得是定义得极其清楚的大迁移。

编排界面会长什么样，Warp 内部还在争论做一个产品还是拆成两个。它更像 web 端的东西，用户群可能不同；但打包在一起有个大好处，云端任务到本地的交接非常顺滑。他举了自己的例子：在 Slack 里 tag 一下智能体，让它改个按钮位置，云端干完活，拉回本地继续打磨。界面会更像任务管理，但他不认为任务管理会取代代码成为开发者的核心原语，没有开发者会整天活在 Linear 和 Jira 里。

六分的编程，和被「解决」的预言

回到开头那个六分。Lloyd 天天用自家产品在 Warp 的大型 Rust 代码库上干活，他的体感是：中等复杂度的任务，给足指导，智能体做得挺好；整个大项目不行，基础架构决策他不敢放手。它远超改按钮颜色这种琐事，0 到 1 很强，也能解挺难的 bug。最近他给 Warp 加一个新斜杠命令，在 Slack 里 tag 了智能体，对方产出一个 300 行的 PR，基本正确。

瓶颈他也列得很清楚。上下文窗口依然是大问题，模型对整个窗口保持合理注意力很难。没有持续学习，每次任务都像一个大而无状态的东西从零开始，靠重新灌文件填上下文。另外，怎么用好这些工具本身还处于蛮荒期：Warp 团队内部的使用方差都很高，写代码有极严格的标准，用智能体几乎没有任何标准，没人教过，也没有公认的最佳实践。

错误率方面有个里程碑：现在智能体的产出编译通过率接近 100%，四五个月前编译通过还是个坎。但带 bug 的产出依然频繁，缺的是「功能到底好不好用」的验证闭环。Lloyd 认为出路在 browser use 和 computer use，让智能体改完代码后从用户视角验证一遍，而非只从代码视角。有了这个闭环，强化学习才能优化「行为正确」，而不止「编译正确」。远程执行的智能体越多，这件事越关键。

主持人问，会不会迎来超级智能时刻，模型超越最强的人类程序员。他的回答是「完全不知道」。但他确信一件事：编程会被模型解决，到时的限制因素是人类清晰表达意图的能力。要造什么、怎么造，英语是模糊的。

这里有个漂亮的反转。主持人追问，编程难道是最精确的意图表达？他承认是，但世界正从「用代码说话」搬向「用英语说话」，等于重新引入了一层模糊：开发者不再直接写出想要的逻辑，而是隔着一层翻译，把需求说给模型听。好在这样效率高太多了。

这个判断还有一层竞争推论：等意图匹配不再需要最前沿的模型，卖编程 token 的 API 生意就危险了，撑不起高毛利。这正是 Anthropic、OpenAI、Google 拼命冲应用层的原因，API 层的风险太大了。他补了一句，这是预测，不是断言。

企业客户怎么看这笔账？目前还把它当生产力工具评估，靠工程师的主观感受和 DORA 指标，很难量化。拿 20 万美元的智能体去替换 20 万美元的工程师，企业的反应是「没门，差得远」。什么会改变这一点：出现没有工程师参与就上线的产品，成本一对比就清楚了。他顺带说了句真心话，他工程师出身，不希望任何人失业。

三年前的「Ask and Adjust」，今天依然成立

对话收尾聊到他 2023 年的一篇博客。ChatGPT 刚发布后，他提出生产力界面会从手工编辑转向「ask and adjust」：过去所有工具都为手工编辑设计，Figma 画矢量、Sheets 填格子、VS Code 敲代码；以后主界面变成让应用替你做事，人负责调整，重新提示，或者退回手工编辑收尾。

他当时还有个判断：越是可以接受的答案足够多的领域，越不需要调整环节。创意领域一张图有一千种合格，重掷骰子就行；代码和表格这种只有一个正确答案的地方，手工编辑能力必须留着。三年过去，他说这个论点「不算差」。

彩蛋一个：agent mode 这个行业通用词是 Warp 发明的，他们是第一个把它做成品牌功能名的产品。Lloyd 开玩笑说，早知道该注册个商标收授权费。

最后，几条明天就能用上的东西：

  • 让智能体干活前，先和它一起做一份计划，跑起来后定期回来检查。20 到 30 分钟是当前无人值守的合理上限，超时大概率在绕圈。
  • 把手工编辑降级成备用手段，主力时间花在两件事上：把意图写清楚，认真审查 diff。提示词质量是目前产出方差的最大来源。
  • 给仓库做一次上下文工程：理清结构、写明约定，让智能体进来就能干活。连 Warp 自己的团队都没有统一用法，这里的投入回报很高。
  • 选工具别只比价格。模型能力正在拉平，harness 和产品体验才是差异所在。日常用 auto 路由，关键任务手动指定模型。
  • 验证别止步于编译通过。让智能体自己跑测试，能上 computer use 就让它从用户视角把功能点一遍。行为正确比编译正确值钱。
