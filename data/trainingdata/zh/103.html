《把近200万美元营收全退给客户，Factory CEO 把软件「黑灯工厂」讲透了》

先讲一个少见的公司操作。Factory 创业头两年，营收爬到了将近200万美元。然后 CEO 决定：把这些钱，全部退给客户。

理由很直接。销售把东西卖出去了，开发者用得却不开心。继续收钱等于埋雷，客户迟早流失，口碑一起赔进去。于是全退，并承诺三个月后再来，这次保证让客户满意。

讲这个故事的人叫马坦·格林伯格（Matan Grinberg），Factory 联合创始人兼 CEO，公司做软件开发的自主智能体，内部叫 droids。这是他第二次上红杉的播客 Training Data，主持人帕特·格雷迪（Pat Grady）说，能二刷的嘉宾是少数，他们算这个赛道里的黑马：前面有 Claude Code、Cognition 这些领跑者，Factory 正在追上来。

这期对话密度很高：怎么熬过「早两年等于错两年」的沙漠期，为什么支持多家模型的 harness 反而比模型厂自家的更强，token 的钱该怎么分配，以及一个具体预测：12到24个月内，90% 的 token 会变成异步任务。逐段拆。

早两年，和错两年，是一回事

Factory 成立于2023年4月。那时候企业市场连 GitHub Copilot 都刚消化完，全自主智能体纯属超前。马坦形容头两年是「沙漠之旅」：方向后来被证明是对的，但工程师没准备好，企业采购更没准备好。

帕特想夸他愿景超前，他的回应成了这期节目的金句。

「提前两三年，和做错，是一回事。」

他的解释很实在：没人给「早」发奖金，没有安慰奖，要么做成，要么没做成。他本人从博士退学创业，之前从没上过一天班，企业销售对物理学家完全是陌生领域。两年里，他说服了20个自己认识的最聪明的人辞职加入，这些人有家庭有孩子，陪着公司一家家客户敲门。

沙漠没白走。他们摸清了企业客户最在意的底线：模型独立性，别让任何人掌握自己的命运。企业吃过云时代的亏，AWS、Azure 当年签三年长约，补贴价便宜得很，续约时直接翻十倍。想跑？先来一次两年的迁移。所有人都留了疤。

所以面对 Claude Code、Codex 这些自带分发的产品，Factory 的打法是：企业照样能用到顶级模型的性能，但不被任何一家模型厂锁死，新模型更快更便宜，直接热插拔。

帕特追问：那会不会只是把锁定对象换成了 Factory？马坦的回答是，所有自动化脚本、技能注册表、配置产物都留在客户自己的代码库里，Factory 手里没有扣着不放的「部落知识」，帮客户做模型套利省下的成本也归客户。建立信任的方式，是让客户随时可以走。

退钱的逻辑：让客户痴迷，才算数

回到退款。驱动这个决策的，是 Factory 的一条运营原则：创造痴迷的客户（create obsessed customers）。

这是对贝索斯「客户痴迷」的一次翻转。马坦认为，对客户痴迷是个输入指标，输入指标不值得考核。原话相当损：

「你可以对客户痴迷到他们给你申请限制令。」

他打了个篮球的比方：教练不会在赛前叮嘱队员「记得出汗」，教练说的是「得分」。出汗是得分的副产品。同理，对客户痴迷是手段，客户痴迷于你才是结果。考核输出，别考核输入。

拿这把尺子一量，当时的产品不及格。于是有了退款，有了那场全员会。马坦说那是他人生最糟的月份之一，会议室里所有人的脸都白了：这是不是沉船前的信号？对投资人也不好开口，他记得跟红杉的肖恩·马奎尔（Shaun Maguire）摊牌：之前那些「营收在涨」的更新，马上要归零了。

团队没散。他的归因有两条：一是早期招人极其狠，只收真正痴迷于「把自主性带给软件工程」这个使命的人；二是不装，直接承认处境有多糟，竞品营收疯涨，我们把营收退光了，必须振作。队里有赛艇运动员，赛艇是纯粹的痛苦运动，一个数字衡量一切。共同熬过谷底，才铸出最深的纽带。

一个背景数字：Factory 起步估值500万美元。马坦说，如今很多竞品生下来就是独角兽，从没体验过缺钱的滋味。而他的团队见过谷底，没有一个人离开。

反直觉：多模型 harness，比原厂自家的更强

转折点很具体：2025年9月26日，Factory 发布 Droid CLI，一个能接入所有主流模型的命令行智能体，性能当时是第一梯队。选时点有讲究，公司成立两年多，市场也终于就位：大多数工程师已经在用自动补全，开始尝试对话式地派活给智能体。

主持人索尼娅·黄（Sonya Huang）问了个自然的问题：模型变强，是不是最重要的变化？马坦说不完全是。最大的变化是开发者，尤其企业里的开发者，愿意放下防备去试了。工程师的工作流花了30年建立，很多人原本的态度是「我的手艺 AI 干不了」。改变靠几股力凑到一起：模型确实强了，要设的护栏少了；组织里更「智能体原生」的同事开始示范；还有 Andrej Karpathy 的推文，他一松口，一批工程师跟着改观。听起来好笑，行为改变就是这么发生的。

接下来是全场技术含量最高、也最反直觉的一段。业界默认假设：自己训模型，自己写 harness，协同设计，效果最好。索尼娅也是这个直觉。马坦说，他那些 OpenAI 和 Anthropic 的朋友听了会沮丧，但事实相反：支持多家模型的 harness，会比单一模型配套的 harness 更强。

他给了一个类比。GPT-3 之前，很多人想用自己的全部数据训练「懂我」的私人 AI，结果答案是：拿整个互联网训练出来的模型，比只用你的数据训练的好用得多。映射过来，数据之于模型，等于模型之于 harness。喂给 harness 的模型越多，越不会过拟合到某一家模型的怪癖，还能把从一家身上学到的技巧，用来改进另一家的表现。

证据很硬：在 Terminal-Bench 被刷爆之前，每个新的 Opus 或 GPT 模型发布，在 Droid 里的跑分都比在 Claude Code 或 Codex 里更高。模型厂当然希望自家模型配自家 harness 才最强，这样用户只能买全家桶。现实没配合。

harness 的功力藏在哪？马坦列了几项：

  • 缓存命中率。缓存命中的 token 价格大约是十分之一，缓存策略直接决定成本。
  • 压缩时的信息保持。长会话会超出上下文限制，harness 要做摘要压缩，业内叫「大海捞针」测试：长线程里埋一条关键信息，压缩后还在不在。
  • 工具调用的稳健程度，能不能用环境验证自己干的活。

他还用两个模型的「性格」举例。Opus 像那个特别好相处的同事，跟它说有20件事要干，它回复：其中5件其实不用干，我换了个更省事的做法，晚上喝一杯？GPT-5.6 则是强迫症式执行者，20件事一件不落，不睡完不成。早年 Claude Code 在 harness 层面严格盯住待办清单，因为模型本身爱跑偏；Codex 不用盯，模型自己就是强迫症。但用户要的是一致体验，换模型，待办清单不能凭空消失。清单为什么重要？一次大规模迁移做到第七步，会话压缩把清单弄丢，智能体忘了第七步是什么，故障就来了。

顺带说基准测试。Terminal-Bench 是他们当年力推的，比偏 Python 单文件改动的 SWE-bench 更贴近真实开发，如今已被刷到90%分。好基准的半衰期只有三到六个月，很快进训练数据。

token 的钱，从狂刷走向分配

节目里有一段企业 AI 采购的阶段性总结，相当生动：

  • 阶段零：没人信 AI。
  • 阶段一：全信了。董事会问 CEO，你的 AI 战略呢？CEO 回头吼 CTO，让所有人都用起来。
  • 阶段二：CTO 把 AI 使用量写进绩效，公开排名谁用的 token 最多，因为工程师固执，不推不动。
  • 阶段三：token 狂刷。所有人拿最贵的 Opus 干一切，包括问旧金山今天天气。

马坦说，有合作的银行每个月花几十万美元，就花在「天气怎么样」「讲讲 Python」这种谷歌一下就有的问题上。根源是当年太怕没人用，矫枉过正，不计代价换采用。他觉得这个顺序反而对：先证明有用，再谈成熟，比一开始就限制用途快得多。

Factory 的解法是 Router，按任务动态路由模型。问天气用不着人类智能的最前沿；COBOL 老代码库，微调过的专用模型可能比 Opus 合适；要可靠性，可以 OpenAI 生成、Anthropic 测试、Gemini 复查。路由规则甚至能用自然语言写，比如「别让 Pat 用开源模型」。索尼娅补刀：那就给 Pat 上 Gemini Flash。

开源模型的进展是另一个数据点。马坦对 GLM 5.2 的评价是「不可思议」：Factory 内部工程师不设 token 上限，一半的内部 token 流向开源模型，更快、更便宜、性能不差。他提醒一个常见的比较错误：GLM 5.2 该对标上一代的 Opus 4.7 或 GPT-5.5，拿它跟最新款比当然差半代，开源模型天然晚一步。真正该问的是：开源模型能不能追平「前沿减一代」？答案明确是能。

趋势数据：年初，Factory 客户侧流向开源模型的 token 不到1%；一季度到个位数百分比；现在已经跨入两位数。他的预测是，token 份额最终会渐进趋向开源占绝大多数，因为更便宜、选择更多，但永远到不了100%。前沿智能永远有价值，关键决策的那1% token，杠杆完全不同。

他管这套思路叫智能分配，配了个生活版：给女儿找代数家教，不用请爱因斯坦，高中生就够了，除非她将来要当物理学家。推到工程师身上同理：一天里大部分时间脑力占用其实很低，写文档是典型。Stripe 靠顶级文档吃过红利，但让最聪明的工程师花几小时写文档，是低杠杆用法。把低杠杆时刻全部自动化，让「灵光一现」从一天几分钟，变成一次几小时。

商业模式也顺着这个逻辑走。现在按用量计费，跟客户利益对齐，按席位没道理；他判断2030年代会走向按结果付费。他描述了一个准市场形态：买方是要完成任务的工程师，模型厂按任务报价竞标，报高了亏本，报低了没利润，成败由验证闭环判定。任务怎么切分还是难题，但工具越强，切分越容易。

黑灯工厂：把公司当一个 AGI 来调参

公司名字的来历也交代了。灵感之一是特斯拉工厂，机械臂满场跑，马斯克说工厂是「建造机器的机器」。终极形态叫「黑灯工厂」：灯全关着，生产照常进行。Factory 押注软件开发正在走向这个形态。

马坦对现状的判断很刻薄也很准确：每家公司其实都已经有一个软件工厂，只不过极其低效，像前工业时代的手工缝纫。一家万人以上的公司，一个功能从决策到发布，流程里牵扯几百甚至上千人，而且大概率没人能把这条流程画出来。靠的是「去问那个干了30年的老师傅」、层层审批、某份没人记得的检查清单，全是部落知识和人工冗余。

他引用了杰克·多西（Jack Dorsey）的一篇博客：每家公司都像一个 AGI。既然是 AGI，就该优化权重，搞清楚哪些节点承重、哪些节点该加 token、哪里该加节点。训模型不能靠感觉做反向传播，得真跑数字。现实里的公司呢？token 预算靠拍脑袋，裁员两万人也靠拍脑袋。不可能有什么科学能论证两万这个数字，那就是先砍一刀看看。

往后推两年，CIO 要回答的问题会从「每个增量 token 给谁」变成「每个增量美元给谁」：加人头还是加 token？加到哪个部门？销售团队加 token 大概率没用，好销售的价值在跟客户面对面坐下来的那段时间；工程团队加 token，产出实打实涨。这些判断需要数据闭环：功能上线，留存动没动，使用量动没动。马坦说，十年后回头看现在这个软件时代，会像看到不做记账的远古生意。帕特补了一句：像《广告狂人》里的营销，全凭创意，没人知道什么真的有效。

由此是核心竞争力的重新排布。马坦见过反例：一家消费物流公司坚持自研软件开发智能体，半年后想明白了，核心竞争力是物流，雇 AI 工程师干这个纯属浪费。类比很简单：互联网早期，开披萨店得先雇程序员做网站；今天没有披萨店设工程部门，也没人觉得可惜。AI 会逼所有企业做一次冷酷的聚焦：核心的事加倍下注，其余的外购。

对未来的预测，他给了一个具体数字：12到24个月内，90% 的 token 会是异步的。现在的 Claude Code 用量看着凶猛，但全是同步的，工程师哪天集体病倒，用量直接归零。真正的智能体原生时代，是 droid 自己在后台跑：发现一条客户信号，自己动手修，或者先出个初版方案。灯关着，活照干。

他也泼了冷水：短期会有剧烈动荡，很多公司错配了资源，组织虚胖，纠正的过程会非常痛，他认为每个 AI 公司的 CEO 都该为此承担比现在更多的责任。长期他完全不信「工程师要消失」。世界上问题很多，一大类可以用软件解决，真正被软件解决的只是一小部分。被释放出来的工程师，会流向那些从没被解决的问题，从政府网站这种糟糕体验，到制药研发这种长期缺软件人才的领域。他给行业的期许是，这个重新分配别花十年，争取六个月到一年。

明天就能用的五件事

聊到客户怎么完成这场转型，马坦给的答案朴素得意外。表现最好的客户，做的往往是同一件事：全公司黑客马拉松。划出一天，所有人放下手头工作，就用 AI 造东西，造出来一塌糊涂也没关系，重点是定下基调。EY 是他们最大的客户之一，算不上 AI 前沿公司，态度却很明确：之前的转型迟到过，这次不迟到了，搞砸就搞砸，先跑起来。

另外两条分野：敢喊「没有圣牛」，把现有流程整个推倒试新方案，不行再放回去；变革由内部发起，来自技术团队和一线，比董事会空降的指令成功率高得多。

最后是可以直接抄的清单：

  • 考核输出，别考核输入。别统计团队「用没用 AI」，去统计 AI 参与的工作有没有真的改善留存、使用量这些结果指标。
  • 给每个增量美元做分配决策：加人头还是加 token，加到哪个团队。销售加 token 基本无效，工程加 token 回报明显，先从这两个极端校准。
  • 别把命运押在单一模型上。按任务路由，写代码、测试、复查可以分属不同模型，COBOL 这类老系统试试微调专用模型。
  • 写验证标准时往死里严格。智能体为了通过测试，是会把代码整个删掉的，「问题解决了，因为代码没了」。
  • 如果团队还没动起来，先办一天全公司黑客马拉松，允许失败，别设圣牛。
