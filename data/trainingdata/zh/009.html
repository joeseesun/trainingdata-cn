《AI 写了 25% 的代码，GitHub 自己都不信：Copilot 诞生记与十亿开发者野心》

2021 年，Copilot 预览版的数据第一次跑出来：在开启这个功能的文件里，25% 的 Python 代码由 AI 完成。

GitHub 团队的反应很真实。他们让工程师回去重新核实遥测数据，因为没人相信这个数字。

四年过去，当初没人敢信的产品，付费订阅者超过 180 万，覆盖 5 万多个组织，两年做到 1 亿美元 ARR，是生成式 AI 领域仅次于 OpenAI 本身的增长故事。GitHub 整体营收增速 45%，微软 CEO 纳德拉在财报会上亲口说的。GitHub CEO 托马斯·多姆克（Thomas Dohmke）做客红杉播客 Training Data 时，还顺手纠正了主持人口中的 40%：「纳德拉说的是 45%。」

这期节目内容很密，挑重点讲。

从东柏林的地理教室，到微软收购案的核心

多姆克 11 岁第一次见到计算机。那是柏林墙还立着的年代，学校地理实验室里有一台机器，他和一个朋友轮流摆弄。那个年代想用机器就得先会写代码，连加载一个程序都要懂点 BASIC。

墙倒了，他买了 Commodore 64，后来是一台 386 DX-40。90 年代末他做保险软件，那时大部分保险经纪人连软件都没有，有人对着大型机干活，更多人面前只有纸。再后来他去南德给奔驰写代码，然后创业，公司被微软收购。

把他推到 GitHub 门口的是 2018 年那笔收购。当时他是微软产品经理，汇报给 Nat Friedman。Friedman 提出买下 GitHub，带着几个手下琢磨怎么把方案递到纳德拉和董事会面前。交易在 2018 年 6 月 4 日公布，多姆克出任交易整合经理，一个要跑遍微软全公司、把法务、HR、财务、产品、工程拧成一股绳的岗位。整合完成，他留在 GitHub，一路做到 CEO。

他说当年的收购文档里其实有一小段提到 AI，但那更像一句愿景注脚。Copilot 靠的完全是一场计划外的实验。

一次 Zoom 会议，敲出了 Copilot 的第一行代码

2020 年 6 月，全世界居家隔离，GPT-3 刚给 GitHub 开放早期访问。一次内部视频会上，团队成员 Oege de Moor 开始往模型里敲东西，其他人凑在屏幕前看。很自然地有人问：能让它写代码吗？能写出正经代码吗？

那是第一个「原来可以」的时刻。模型真的写出了正确语法。接着他们试了不同语言，也摸到了模型的缺陷，于是把实验升级成正式研究：让内部资深工程师提交编程练习题，再从 GitHub 开源仓库抽取真实的 Python 函数，和 OpenAI 一起微调 GPT-3。

8 月，微调后的模型解出 92% 的编程练习题。开源项目里抽出的 Python 函数体，正确率 52%。后者看着低，但练习题的描述总是清晰的，真实代码的上下文模糊得多，这个数字反而更有含金量。

第二个信心时刻来自内部。2021 年初工具交给自家工程师，NPS 冲到 70 多。多姆克说，开发者是出了名的怀疑论者，口头禅是「别碰我的系统」，每个人的工作流都在虚拟桌面上摆得整整齐齐，这个分数放在开发者工具里相当罕见。

然后就是那个 25%，以及 2022 年 6 月他作为 CEO 的第一次主题演讲：Copilot 在开启的文件里写了 40% 的代码，他预测五年内到 80%。

连名字都是个内部玩笑。首席架构师 Alex Graveley 想出了 Copilot 这个词，因为他的老板 Nat Friedman 是个业余飞行员。老板一听就喜欢了。

为什么 Copilot 成了？多姆克的总结很朴素：模型够好只是及格线，真正关键的是钻进了开发者已经写代码的编辑器，不打断任何人的工作方式，只在你敲字的时候递想法。他拿手机打比方：键盘早就用机器学习预测下一个词，相册早就能用图像识别搜车牌，没人管这些叫 AI，大家只觉得好用。Copilot 赢在「无感」，它去开发者所在的地方，让日子好过一点。

还有一个常被误解的细节：GitHub 没给 OpenAI 任何数据特权。OpenAI 拿公开源代码，走的渠道和今天任何创业公司一样，要么 GitHub API，要么 Internet Archive、Software Heritage 这类归档项目。GitHub 甚至和后两者有正式合作，把开源代码流式存档，「直到时间尽头」。

那 GitHub 为什么不自己做模型？多姆克的答案一点不含糊：不可怕。GitHub 生在云端，从来没自己造过硬件，数据中心、CPU、内存、网络全是别人的，GitHub 本身就构建在开源之上。他引了一个数据：如今大多数应用哪怕闭源，90% 的技术栈都建立在开源社区的成果上，从 Linux 到 Docker、Kubernetes，再到成千上万个开源库。模型只是技术栈里新的一层，没必要因为它是新的，就打破分工的常识。这套分工换来的是速度：OpenAI 从 GPT-3 一路迭代到 GPT-4o，微软建训练超算和全球推理网络，法国的开发者连就近的 Azure 实例，延迟低到自动补全足够顺滑。快问快答里被问到 AI 的价值沉淀在哪，他的答案也是同一个逻辑：整个技术栈，硬件、模型、基础设施、应用，一层都跑不掉。

当然，工程师永远想造自己的东西。多姆克不否认团队玩过自己的想法，GitHub 的机器学习团队历史甚至早于微软收购。他们也做微调，正在帮客户基于自己仓库的代码定制模型。但今天，他们对市面上的模型很满意，同时盯着 OpenAI 之外的所有选项。永不说不，眼下没这个必要。

180 万付费用户，最硬的指标是幸福感

问到最自豪的数据，多姆克的答案和收入无关，是开发者幸福感。调查数据显示，开发者熬过最初的怀疑期之后，大多数人报告自己更有满足感、更快乐，完成工作需要的脑力更少，样板代码写得更少。用过一段时间 Copilot 的开发者，几乎没人愿意回到没有它的日子。

他自己家的孩子已经不找他 debug 了。孩子们用 Copilot 在 Python 里找自己的 bug，以前是「爸爸你必须帮我找 bug」，现在被一句「自己找去」打发。他觉得这才是关键：自然语言会降低编程的门槛，但买了吉他不会让你变成滚石乐队的 Keith Richards，任何一个世界巡演的职业乐队都还在一遍遍排练。工具降低的是入门成本，练功这件事永远在。

Agent 和 Copilot，其实是一回事

2024 年 GitHub 的产品节奏快得眼花：Copilot X、Copilot Enterprise、代码安全产品 Autofix、最新的 Copilot Workspace。多姆克说这背后是一个信条：动量就是能量，AI 时代必须快跑快迭代。

几个关键拼图：

  • Copilot Enterprise：把公司自己的机构知识喂给 Copilot。每家成立超过几周的公司都有「我们这儿怎么做」的隐性规则，新人入职最痛苦的就是不敢问蠢问题。有了它，新人可以放心问 AI「为什么这里的代码这么写」，不用担心同事心里翻白眼。
  • Autofix：传统安全扫描像一台只会告诉你哪里脏的 Roomba，扫出 SQL 注入、跨站脚本，然后你自己去擦。Autofix 直接把修复方案一起给出来，部分客户的开放告警，它能消化掉 75% 到 80%。
  • Copilot Workspace：从想法到拉取请求的完整链路，拆成三个 agent。spec agent 帮你梳理想法，它甚至会对产品经理说「这个想法一句话讲不清楚，一个 ticket 装不下，得拆成 epic」；plan agent 定位代码库里该改哪些文件；implement agent 动手改代码。每一步人类都握着方向盘，可以用自然语言修改中间产物。
「如果你现在没有安全告警，我打赌周一早上你就会有了。」

至于 agent 和 copilot 的区别，他的回答可能让炒作 agent 的人失望：本质是一回事。agent 就是拿模型循环干活，copilot 是 agent 的 agent，手里有多个功能可调用。自动补全本身就是个 agent，每次按键都把上下文发给模型推理，挑最好的预测展示给你。他预计未来会出现更多这样的积木，就像乐高今天的零件种类远比过去多，因为要拼 NASA 火箭，就得有新零件。

聊到 agent 能力的时间表，他在快问快答里给了两个年份：SWE-bench 上 agent 通过率达到 50%，2025 年；90%，2028 年。说完他自己补了一句，最后一个答案还是太保守了。

孩子还要学编程吗？这个德国人的答案很较真

这是互联网上吵翻的话题，多姆克的回答带着工程师式的较真。人类语言有歧义，同样一句话可以有好几种意思，美国人被问「你还没去超市啊」的时候，期待的回答是 no，尽管你实际的意思是 yes。代码没有这个问题，代码可以精确描述机器的行为，它是架在 CPU 指令集上的又一层抽象。

只要芯片还吃确定性的指令集，自然语言和机器之间就永远需要一次到代码的转换。抽象层在升高，写代码的人在变多，但代码不会消失。所以他坚信孩子该学编程，只是学的方式变了。

他的野心写在今年的 TED 演讲里：让全世界的软件开发者达到 10 亿。重点未必是 10 亿职业程序员。他想让 2030 年前后的地球上，大约 10% 的人具备写点小程序、小脚本的能力，用自然语言指挥自己的手机。他期待下一个科技巨头从印度或者巴西这样的地方冒出来。

聊到 AI 能不能长出创造力和系统思维，他给了一个冷静的判断。模型今天平均而言已经能写出比普通开发者更好的代码，前提是提示词和上下文给得对。学生写 100 行二进制转十进制，问 Copilot 一行开源库调用就解决了。但写代码只是软件开发的一部分，真正的难点是把一个复杂问题拆解成小块，然后在成千上万个技术决策里做选择：用什么数据库，选哪家基础设施。工程师是做这些决策的系统思考者。人类盖了几千年房子，盖房子依然是个未解决的问题。

至于模型会不会长出意识，他搬出了自己的孩子。他的小孩在家说德语，在外面说英语，两种语言都没有口音。孩子靠模仿周围的人学语言，这种能力今天任何 transformer 和扩散模型都够不着。他没看到任何研究显示「意识那一块」快要被补上了。

那五年内会不会出现超越 transformer 的新架构？快问快答里他的回答是「当然会」。transformer 之前本来就有别的架构，新架构出现也不意味着取代，就像 GPU 再当红，你的手机里 CPU 依然在跑。这个判断对生态里的建造者是个好消息，意味着大量需要重做和重新架构的空间。

给创业者和巨头的话，和明天就能用的三件事

红杉的主持人问他，AI 代码生成是最卷的赛道，Copilot 横在眼前，新创业者还有活路吗？他讲了一个历史故事：GitHub 创立时，房间里的大象叫 SourceForge，所有开源项目都在那儿。然后 Git 出现，GitHub 的创始人拿 Git 造了 GitHub，大象就不在了。竞争让他兴奋，「没有对手的比赛谁看？超级碗年年只有一个队赢，谁还看？」

他点了一个具体的空白：遗留代码现代化。COBOL 还跑在大型机上，你的信用卡、银行账户、华尔街的交易系统背后都有它。他说没见过一家不跑 COBOL 的银行。写那些代码的人早就退休了，今天 Copilot 能解释这些 60 年前的代码，能帮它们补单元测试，60、70 年代没人写单元测试，那会儿连硬盘都还没有。但一键重写还做不到，PHP 和 Java 的老代码库里同样堆着大量优化空间。

给创业者的建议有两条。第一，聚焦，白板上永远能写下更多想法，敢对它们说不。先做产品驱动增长，让一群兴奋的开发者替你传口碑，企业大单会晚一点来，反过来先做企业再回头做开发者，反馈回路差太多。第二，想大一点。今天在模型上包一层的小想法，明天就会被商品化，创业公司需要十年尺度的愿景，再把它拆解成眼前能解决的小问题。

给巨头的建议更扎心。有人写信问他，大公司是不是真的快不过创业公司。他的答案是「radical focus」：有 1000 个工程师不等于什么都能做，这是个错觉。团队规模变大，你反而失去了感知系统摩擦力的单位。然后是战略取舍，战略的意思是想清楚凭什么收得上价钱，别打价格战。

「GitHub 平台上几乎没有什么东西是砸钱砸时间重建不出来的，但我们的文化、我们对开发者的执念，很难模仿。」

战术上，GitHub 的做法是 GitHub Next，一个内部孵化团队。规则很残酷：大部分想法永远进不了生产环境，团队的关键结果就是扔掉大多数点子。原以为做的是五年后的项目，结果发现只领先主线六个月，未来扑面而来的速度超出预期。所以孵化团队必须快速把东西交给主线工程团队，同时砍掉旧项目，或者把它们调到「维持灯亮着」的模式。多姆克承认这是转型最痛的部分，创业公司也一样，只是小公司有更强的外力逼自己放手。启动方式倒简单：demo，别写备忘录。用现成的 React 组件或者 Figma 拼个原型，判断标准是用户反馈的飞轮转不转，是试用就流失，还是用户追着喂新想法。

这期播客的信息量很大，收拢成三个可以马上做的动作：

  • 如果你还没把 AI 编码助手装进日常，先装上，然后量一个 GitHub 用过的指标：开启它的文件里，有多大比例的代码由 AI 完成。25% 是 2021 年的起点，40% 是 2022 年的 keynote 数字，你团队的数字本身就是决策依据。用过的开发者几乎没人回头，这个信号比任何评测都硬。
  • 如果你管着一个堆满安全告警的 backlog，别再把扫描工具当待办清单生成器了。看看 Autofix 这类「连修复方案一起给」的产品能不能消化你 75% 以上的开放告警，扫描和修复之间的那段人工，才是真正的瓶颈。
  • 如果你在带团队或者创业，把「radical focus」写进下周的会议：列出手上所有项目，明确哪些进孵化、哪些维持灯亮、哪些直接关掉。多姆克的原话值得贴在墙上：有再多工程师，也不等于什么都能做。

最后是他留给所有学编程的人的一段话，也是这期节目里最像人生建议的部分：买了吉他，你依然弹不成 Keith Richards。工具会越来越好，排练这件事，一天都不会少。
