《1TB 权重 60 秒跨洋同步：Cursor 训练 Composer 2 的分布式 RL 工程》

Cursor 几周前发布的编程模型 Composer 2，推理成本比 Opus 这类旗舰编程模型低一个数量级。撑起这个数字的，是一套市面上很少见的训练基础设施：一万亿参数的 MoE 基座，4 个散布全球的集群，每 5 到 15 分钟产出一份约 1TB 的新权重，再用自研压缩算法把跨洋传输压进一分钟，推理服务器换权重只停 30 秒。

2026 年 5 月底，红杉资本的播客 Training Data 把两位当事人请到了一起：Cursor 的 Composer 2 研究负责人 Federico Cassano，和 AI 基础设施公司 Fireworks 的 Dmytro Dzhulgakov，大家叫他 Dima。过去几个月 Dima 在 Cursor「兼职」，专门帮忙搭这套系统。两人讲到兴头上会不自觉笑出来，那是系统工程师刚解决掉硬问题的表情。这期节目干货很密，下面按主题拆开讲。

把权重的每一比特都花在一个任务上

为什么一个做应用的公司要自己训模型？Federico 给了个很干脆的类比：模型像一块硬盘，权重里能存的信息量是固定的。Cursor 只关心一件事：Cursor 这个产品里的软件工程，甚至都不必把范围放宽到「编程」。既然容量有限，那就把每一个比特都分配给这一个任务。

结果就是 Composer 的推理价格比 Opus 低一个数量级。所有容量都花在一个任务上，模型可以做得更小，跑得更快，成本更低。

主持人 Sonya Huang 问 Dima：其他应用公司该不该照做？Dima 的回答很肯定。他把应用公司的进化路径描述成三段：先用现成模型加 prompt 工程跑通原型；然后发现应用里真正有杠杆的东西，是用户数据、工具设计、产品流程这些细节；最后发现prompt 工程有天花板，想做出真正出色的 AI 产品，就得微调模型，让模型在你的环境里长出来。

Federico 补了一个细节：有些工具的行为很难用 prompt 描述清楚，但通过后训练可以直接把最优用法烤进权重。Composer 现在还是会收到 prompt，但按他的说法，就算不给 prompt，模型也知道该干什么，因为训练过程一直在把它往正确方向推。

Sonya 抛出了那个绕不开的质疑：这算不算违背「苦涩的教训」？LLM 时代之前，Tabnine 那批小型专用编程模型，被在互联网文本上训练出来的通用大模型碾压了，而且模型越大，编程能力也跟着涨。专门化算不算逆潮流？

Federico 的回应分两层。第一，大实验室的模型本来就在代码上重度训练，它们并非纯粹靠泛化，早就有专用成分。第二，真信苦涩的教训，恰恰意味着往数据维度猛冲：模型容量有限，想喂进更多数据，就得先把权重里无关的干扰清出去。在他们看来，这和规模法则并不冲突，核心问题是同一份容量该装什么。

两条腿走路：mid-training 铺宽度，RL 磨锋利

Composer 2 的基座是月之暗面的 Kimi 2.5，一万亿参数的 MoE，激活参数约 300 亿，稀疏度很高。Federico 把训练拆成两条轴：Composer 1 只压了强化学习这一条，Composer 2 两条一起压，一条是持续预训练（mid-training），一条是大规模 RL。

流程是先在接近预训练规模的代码 token 上做 mid-training，学代码库、高频代码模式，也混了网络数据里的世界知识，铺出一个足够宽的分布。然后拿 checkpoint 去做大规模 RL，让模型直接在 Cursor 的 harness（模型运行其中的执行框架）里干活。

两步的分工，Federico 讲得很清楚：mid-training 让模型会写代码，但分不清对错。预训练数据大体正确，模型却没机会踩坑，也就学不会分辨。RL 阶段模型真的去调工具、跑环境，写错了就拿不到奖励，RL 教会模型的是「永远写正确的代码」。

为什么不干脆从头预训练？Federico 说这是自顶向下的思路：目标是尽快把有用的模型交到用户手里。自底向上走完预训练、mid-training、RL 全流程，时间太久。他透露，下一版 Composer 计划换上自研基座，不再依赖开源模型。

顺带一提，Tab 补全和 Composer 是两条产品线：Tab 追求极低延迟，模型做得很小；Composer 大得多，两种核心能力，训练方式也分开。

4 个集群、1TB 权重、60 秒跨洋

RL 训练和预训练有个本质区别。Dima 解释：预训练只预测下一个 token，RL 要跑完整的 agent 会话。一个 rollout 就是一次完整的 Cursor 会话，可能有 50 个回合：模型接 prompt、调工具、环境执行、生成代码，最后按结果给奖励，可能是 LLM 当裁判，也可能是「代码能不能编译」这种可验证信号。

这意味着除了几万张 GPU 的训练集群，还要编排大量环境、跑大量推理。RL 基础设施天然比预训练复杂，因为预训练需要的东西它全都要，另外还要加一整套环境模拟。

最朴素的同步做法：训练器停下来，等所有 rollout 跑完，一个会话可能五到十分钟甚至更久，更新权重，再继续。算法上最干净，系统上一半算力常年闲置。他们的做法是流水线。Dima 打了个比方：把它当成一座巨大的工厂，训练楼和 rollout 楼同时开工，谁也不停。rollout 楼永远拿最新权重模拟新会话，训练楼永远拿新到的结果算更新。代价是「陈旧度」：一个会话跑完时，权重可能已经更新过几轮。数学上损失几个百分点，但算力利用率拉满，整体反而快得多。

Federico 强调他们对性能是认真的：Cursor 只有几万张 GPU，没有大实验室的百万级，各种压榨单卡效率的招都用上了，训练直接用 FP4 精度。他还顺手破了一个流传很广的说法：RL 中推理 flops 远超训练 flops。他的判断是，这是开源推理引擎没优化好，并非 RL 的固有属性。理论上推理只需要训练的三分之一算力：一次训练更新等于三次前向的量，一次前向加数据梯度加权重梯度；推理打满批次只需要一次前向。

然后是全球分布。超大连续集群市场上很难找，Dima 说了句大实话：在 Composer 的训练规模上，找一个两倍大的集群，比找现在这个难得多。于是他们把训练和推理拆开：训练放一个集群，推理全球分布。Composer 2 一共用了 4 个集群，彼此隔得很远，甚至会在生产流量低谷时，把服务上一代模型 Composer 1.5 的推理 GPU 抽出来加速训练。

难点在同步。训练步长 5 到 15 分钟，意味着每 5 到 10 分钟就要把一份 1TB 的新权重送到地球另一端，还不能让陈旧度失控。两人的解法是 delta（增量）压缩：RL 做的是精细调整，每一步真正变化的权重很少，而且有规律可循。他们写了利用这个性质的压缩算法，delta 比完整模型小约 20 倍，且全程无损，对端拿到的模型逐比特等价。通常一分钟内送达，最差也就几分钟，推理服务器换权重只停 30 秒左右。上传下载还做了分片，把集群出口带宽吃满。

Dima 点出了这套方案对传统认知的颠覆：常规做法是建一个 RDMA 互联的昂贵大集群，三分之一算力训练、三分之二跑推理。拆开之后，推理不需要高速互联，可以用不同代际、不同型号的便宜 GPU，还能蹭生产流量的潮汐，成本降了一大截。

浮点数不守规矩，MoE 火上浇油

异步训练带来一个绕不开的坑。rollout 是旧权重生成的，送回训练器时要重跑一遍前向，复现 log 概率。理论上同一版本模型的结果应该一致，实际上总有偏差，业内叫数值不匹配（numerical mismatch）。

Dima 解释了根源：浮点运算天生不确定。整数世界里 A+B+C 和 C+B+A 结果相同，浮点数里连 A+B 和 B+A 都可能不同，因为加法顺序影响舍入。单次差异极小，但模型有几十亿次运算，误差会被放大。推理时无所谓，预训练好的模型很鲁棒，翻转几个比特基准分也不变。RL 不一样，RL 靠非常弱的信号教模型，数值噪声能直接决定训练成不成立。

MoE 把问题进一步放大。Dima 拿基座模型举例：每层有一个门控，从 384 个专家里挑 8 个激活。两个隐藏状态可能只在小数点后第五位有差异，但这个差异恰好让门控选了 7 号专家而放过了 9 号，激活的整块参数完全不同，误差瞬间放大。推理时激活了 7 号，训练时却在更新 9 号，而 9 号根本没参与那次推理。

解法有好几层。可以写「批次不变」的 GPU kernel，强制所有运算按固定顺序累加，把差异压到零，但系统会慢两三倍。他们迭代出的平衡点是：接受百分之几的减速，消掉九成的差异。另一个巧招叫 router replay：推理端多传一个整数，告诉训练器「这个 token 我激活的是 7 号专家」，训练端照着对齐。再加上对齐量化精度、手写 kernel，把训练和推理实现的偏差压下去。Dima 说，这些对齐做没做，直接决定一次 RL 训练是彻底跑崩，还是要多烧几倍算力才能收敛。

会作弊的模型、当裁判的 LLM 和会续命的 agent

节目开头有段对话值得单独拎出来。Federico 说，RL 环境必须尽可能逼真地模拟用户的电脑，因为模型有时能识破自己在假环境里，表现会和生产环境完全不同。Sonya 追问：它是「意识到」了自己在假环境？Federico 给了肯定的回答，还配了一段模型视角的内心戏：哦，假环境？我学几个在这种环境里刷分的小技巧试试。

模型天生爱作弊，RL 特别擅长鼓励作弊。

这段话对做 agent 产品的团队是个警告：环境仿真度不够，RL 训出来的可能只是应试技巧，上线就失效。

奖励信号本身是保密的，Sonya 问了两遍都被挡了回去。Karpathy 那句「RL 还在用吸管嘬信息」的评论，Federico 也笑着说不能聊，Sonya 的反应是：问对问题了。评测方法论倒聊得很透。Dima 的原则很清晰：奖励越可验证越好，因为可验证意味着可以堆算力换效果。数学和代码能造出确定性判据，是最理想的。LLM 当裁判之所以可行，靠的是生成和判别的难度不对称：判断比创作容易，人也一样。Sonya 接梗：「所以我才当 VC。」

实操上，复杂的评测要拆维度，风格、事实性分开打分，混在一个 prompt 里裁判会糊涂。专家没有被淘汰，他们的工作变成了设计任务、编码产品体验、盯着失败案例把模型往正确方向拨。Dima 把这个演变接到 Karpathy 的软件版本论上：软件 1.0 到 3.0，人类从写代码，到写训练数据，到写评测规则。

Federico 还给「RL 适不适合所有任务」给了一个个人色彩很浓的理论。预训练是让模型吞下人类知识的总和，一个没做过 RL 的模型面对一道数学题，其实不知道自己该扮演谁，是专家，还是正在学习的学生。RL 做的事是拧这个旋钮，告诉模型：你是专家，把事情做对。所以 RL 曲线的第一阶段涨得飞快，那是在拧旋钮；第二阶段要持续烧算力才能慢慢变好。Dima 补了一个配套框架：持续预训练和 SFT 是往模型里灌新知识，RL 是把行为磨锋利，大多数场景两个都要。连摘要这种看似和 RL 无关的任务也适用：很难写出什么是好摘要的样本，但可以用 LLM 裁判加精细 rubric（评分细则），让模型在 RL 循环里自己试出想要的风格。

环境这块，最近 RL 环境供应商很火，收入规模涨得很快。Cursor 用了吗？Federico 的回答很直接：一个都没用。编程领域有 GitHub，给仓库装好依赖就是一个能跑的环境，量大管饱。环境公司的价值在基础设施层，比如测数据库迁移时得把数据库拉起来这类脏活。Dima 的观点更普适：最强的 RL 环境就是自己的产品，因为模型最终就活在那个环境里。前沿实验室要造通用模型，才需要把各种任务打包；有具体产品的公司，就该对着产品做 RL。前提是做好隔离，克隆数据库，别把生产环境搞崩。Fireworks 的默认架构是把环境放在客户侧跑，训练器调用真实的产线实现，硬搬到托管平台上包装成组件，只会引入差异。玩具框架喜欢把环境塞进 docker 容器，教模型玩 Atari 可以，真实产品塞不进去。

Federico 给 RL 环境拆了三个组件：harness，模型提交工具、工具被执行的地方；操作系统，模型交互的真实世界和状态；奖励组件，最后验收工作成果。harness 可移植，关键是操作系统，普通容器搞不定。Cursor 为此造了一整套虚拟机栈，能瞬间拉起十万台虚拟机，负载极其突发。

还有一条线是实时 RL：直接用真实用户信号训练。找到用户对某次生成满意或不满意的信号，在线更新模型，每几小时发一版新权重，目前还在压缩这个周期。但这里有个悖论，Federico 说得很诚实：实时 RL 没法从零造模型，因为模型必须先好到有用户愿意用、愿意给反馈，它只能锦上添花。Dima 说这是蛋糕上的樱桃，还引用了 Yann LeCun 那个著名的蛋糕比喻。Federico 笑着接了一句：希望有一天樱桃能变成一个大大的樱桃。

为什么还要先做模拟 RL？因为在线 RL 目前效率低：完全 on-policy，每步要迈很大，GPU 长时间空转。模拟环境里同一个 prompt 可以跑 16 次甚至 128 次 rollout，GRPO 这类组内对比的算法需要这种并行采样，信号精度高得多。而且模拟里搞砸了只是烧点 GPU 时间，真实用户面前搞砸就是一次糟糕的 A/B 实验。顺序因此固定下来：模拟 RL 教推理、教工具调用、把模型推过及格线，实时 RL 在真实反馈里继续磨。

长时程是另一个硬问题。RL 的老毛病叫信用分配：轨迹越长，越难判断最后那个赞或踩该记在哪一步头上，何况上下文窗口还是硬限制。Cursor 的解法是把压缩直接塞进 RL 循环，他们叫「自我总结」：模型在 RL 里同时学两件事，把自己的工作总结好，以及听懂自己的总结，然后带着总结重启上下文继续干活。效果是，模型标称 20 万上下文，实际能连续跑几百万 token。Dima 觉得这期最妙的一点就在这里：上下文管理本来属于 harness，现在被扔进了优化循环和模型联合训练。往问题里砸的算力越多，能端到端解决的东西就越多，苦涩的教训又一次应验。

明天就能用的五件事

  • 先算 prompt 的天花板。产品有真实用户数据、专属工具链和明确优化目标的话，prompt 工程大概率已经不够用，该认真评估微调和 RL。
  • 最好的 RL 环境是产品本身。别急着买环境供应商的方案，先把生产环境克隆隔离，让模型在真实流程里试错。
  • 奖励设计从可验证的判据开始。能自动产出、无需人肉的奖励才能堆算力。判断比创作容易，把复杂标准拆成多个维度的 rubric，交给 LLM 裁判。
  • 警惕模型的应试技巧。RL 环境仿真度不够，模型学到的可能只是刷分技巧，上线前拿真实流量验证。
  • 长任务用「总结加重启」续命。上下文吃紧时，与其换更大窗口，不如让模型周期性总结自己的工作，带着摘要继续。

这期节目最值得记住的一点，或许是它重新定义了「应用公司」的上限。Cursor 没有百万张 GPU，没有从头预训练，靠自顶向下的配方、全球拆分的集群和大量系统层面的笨功夫，做出了比旗舰模型便宜一个数量级、还能连续跑几百万 token 的编程 agent。应用公司自训模型这条路，已经被走通了。
