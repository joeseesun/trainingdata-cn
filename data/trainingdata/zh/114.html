《从4%到18%，成本降到六分之一：Trajectory 要把持续学习做成一键操作》

一个开源模型在 Harvey 的法律智能体基准上，准确率只有 4%。用 Trajectory 的平台训练之后，做到 18%，模型成本还降到了前沿模型的六分之一。

这是红杉播客 Training Data 最新一集给出的数字。嘉宾 Ronak 是 Trajectory 的创始人，这家公司做的事一句话能讲完：让每家公司不用养研究团队，也能训练自己的专属模型。

Ronak 的履历正好串起了这个故事。他之前在 Windsurf，参与训练了编程模型 SWE-1；两位联合创始人，Michael 在 DeepMind 做过 Gemini Robotics，Arjun 在 Apple 做过 Vision Pro。

持续学习，还停在纸地图时代

先说定义。Ronak 眼里真正的持续学习，参照物是人脑：在线学习，随时更新，越用越聪明。现在的 agent，他叫它「伪持续学习」，模型很聪明，但想让它进步，得攒一批数据，做一次整批的离线训练。

他打了个比方，来自童年的自驾游。

「出发前要去 AAA，就是美国汽车协会，他们给你一堆纸地图，路线全画好了。中途想改路线，只能打电话，或者再跑一趟门店。我们现在就在这个阶段：agent 很聪明，像有了很好的地图算法，但每次想更新路线，都得做一次整批更新。」

演进路径也藏在地图的历史里。MapQuest 是第一阶段，地图人人能拿了，但还是离线的，对应现在各家垂直公司自己训模型。Google Maps 是终点：每开一段路，路况、最快路线都在实时更新。Trajectory 想做的，就是把 agent 带进 Google Maps 阶段，让模型在生产环境里边干活边长本事。

上一期节目里，强化学习领域的两位重量级人物 Rich Sutton 和 David Silver 说过，真正的持续学习在今天的架构上做不成。Ronak 的回应是，架构演进其实已经在发生。他举了 DeepSeek 刚发布的 V4.1 Flash：标准 Transformer 的堆叠结构被改了不少，权重里分出了快慢记忆，第 2 层和第 50 层之间还有跳跃连接。大家熟悉的那种层层堆注意力模块的架构，来自 Karpathy 那个著名的 tiny GPT 教学视频，那只是起点。

但 Ronak 给自己选的位置在另一头。架构的仗让实验室去打，他要做的，是把已经验证的技术接进真实世界，补上闭环里缺失的那一层：把公司脑子里「好是什么样子」，翻译成模型实打实的改进。

以前，这件事只有大厂玩得起

过去两年，一些垂直公司开始自己动手。Windsurf 训了 SWE-1，Cursor 训了 Composer。代价摆在明面上：数亿美元级别的研发和算力投入，一支庞大的研究团队，6 到 9 个月才能训出一个前沿水平的模型。即便如此，走的还是顾问式服务，手把手陪着客户做。

转折点来自三个人的各自观察。在 Windsurf，他们训练模型时，喂进去的就是产品里用户的编辑和重试，模型因此越用越准。Michael 在 DeepMind 看到机器人可以部署到真实世界，配上持续学习基础设施，每天都能更新。Arjun 在 Apple 做 Vision Pro，琢磨的是怎么把艺术家的反馈用进多模态基础模型。三个人在做的事，Ronak 称之为同一个「宏大对齐问题」：怎么把真实世界的反馈变成模型的改进。

他很快认定，持续学习会是下一个学习范式。可在大实验室里，他看到的是另一幅图景：DeepMind 这类机构的整个焦点，是训练一个巨型模型，然后分发给全世界。这个商业模式当然赢了，可它有个天然盲区。为单独一家客户定制模型，再单独部署给这一家，需要巨量基础设施，实验室不会为单一客户建这套东西。Harvey 想要专属模型，没人给它开小灶。

Harvey 的处境很典型。这家服务全球律所的公司，一直骑在前沿闭源模型上，界面和产品做得足够好。但他们手里攒着大量数据和领域 know-how，清楚律所真正在乎什么，前沿模型却用不上这些积累。于是 Harvey 基于自己的专家知识，构造了一个法律智能体基准并公开发布，然后用 Trajectory 训练专属模型。

结果就是开头那组数字：准确率从开源模型的 4% 提到 18%，成本是前沿模型的六分之一。18% 看着不高，离天花板还远，但关键在于，一家律所科技公司第一次拿到了研究实验室级别的建模能力。还有一层隐藏收益：模型便宜六倍，意味着完成同样的任务，可以放开手多烧 token。

一条 trajectory，就是一份有经济价值的工作

公司名字里藏着产品观。现在全世界都把 token 当作工作量的单位，Ronak 觉得该换：人和人协作时，没人去数对方说了多少词，大家关心的是一个任务、一条轨迹。在强化学习里，trajectory 是 rollout 的同义词，也就是模型一次完整的执行；放进持续学习的语境，真实世界的推理就是 rollout 引擎，一条 trajectory，就是一份有经济价值的工作。

把轨迹变成模型的改进，Ronak 拆成三步，缺一不可。

  • 记录轨迹。不只记主 agent 的调用，还要记所有子 agent、产品内的行为、用户的每条反馈，理想状态是一条完整时间线。有些公司自建，也有现成工具，比如 LangChain、Braintrust、Raindrop，接进生产环境就能采。
  • 让轨迹可重放。拿到生产环境里的一条轨迹（trace），要能随时重放，给人看「好是什么样子」，也给训练用。技术上这是个环境概念，一份 Dockerfile 或者一份系统依赖清单。Trajectory 的产品帮公司把这一步桥接掉。
  • 改造训练算法。训练栈、损失函数、奖励函数，把任务变成模型的真实改进。这是公司最难自建的部分，也是 Trajectory 最想抽象掉的部分。

前两块是工程活，第三块才是真正的科研难题，Ronak 讲了两个正在攻的方向。

第一个是环境。现在主流的后训练算法叫 GRPO，玩法是：同一个任务让模型跑 8 次或 16 次，组成一个组，组内互相对比。像让玩家反复打同一关游戏，最后结算奖励。问题是，人类学习根本不需要重放同一个环境，一次经历就能学到东西。

Trajectory 的方向是把组的大小从 16 压到 1。他们已经发了博客：拿 1 万条来自不同任务的轨迹，每条只发生过一次，模型照样能学。组大小等于 1，直接消灭了对完美环境的需求。要知道，很多真实工作流根本造不出完美的模拟环境。

第二个是奖励。1 万条轨迹全部人工标注，工作量吓人。Trajectory 的做法是先智能挑出 100 条有代表性的，让客户在这 100 条上密集标注，写清评分标准，然后训练一个「元评分器」，把这套标准泛化到剩下 9900 条。标注成本从万级压到百级。

终极形态，Ronak 描述得很具体：

「理想目标是一个可观测界面：这里是我的 agent 擅长的 5 件事，这里是不擅长的 5 件事，我把要改的圈出来，点一下训练。」

一键训练，和 Apple 式的产品哲学

刚发布的平台，流程被压到极简：把 agent 轨迹和「好是什么样子」丢进去，配几个 agent 提示词，一键训练，评估、部署都在同一个地方完成。训好的模型传回生产环境，收集新轨迹，继续训，循环转起来。

产品哲学，Ronak 明说来自 Apple。2000 年代初，电脑能上网，手机能打电话，两样东西摆在那，没人想到把它们合并，直到 Apple 把互联网装进了手持设备。

「把训练、评估和部署放进一个地方，让每个人都能轻松做到，然后闭环转起来，把模型传回生产环境，收集新轨迹。这会成为一个神奇的新范式，我觉得每家公司很快都会采用。」

Trajectory 做的合并是同一类：把训练、评估、部署塞进同一个地方，简单到每个人都会用，然后让闭环自己转。

目标客户现在很明确：agent harness（套在模型外面的运行框架）已经理顺的 AI 原生公司。Harvey、Rogo 在用，NVIDIA 这样的大公司也在用。

Rogo 值得多说两句，这家做金融 agent 的公司代表了一种新口味。现在大多数人用 agent 是同步的：你发指令，它跑一圈回来，中间可能吐一堆冗长的过程。Rogo 要的是一个简洁清晰的金融 agent，能自主在后台干活，回来时交付的是干货。他们信一个词，智能密度：同样的任务，用少得多的 token 完成。用 Trajectory 训出的模型，token 效率高了好几倍，更便宜、更快，还在 Rogo 关心的指标上持续爬升。

模型和 harness 的分工，Ronak 也划得很清楚。模型给你的是效率：一个任务见过一百次一千次之后，更快、更便宜、更可靠。Harness 给你的是新能力：以前根本做不到的事。很多大公司连 harness 都还没优化好，子 agent 的调度、前沿 token 的最后一公里都没榨干。终局画面是这样的：10% 的任务留给前沿模型，90% 的流量聪明地路由到自己训的专属模型上，利润率立刻好看很多。

顺着往下想一步：产品越来越 AI 原生，harness 正在变成产品本身的大头。谁拿到了自我改进 harness 的权利，谁就拿到了自我改进整个公司的权利。

好奇心、对齐，和园丁式的产品经理

聊到持续学习的下一步，Ronak 从扔橄榄球讲起。第一次拿到橄榄球的人，完全不知道扔出去会发生什么；扔上一百次，心里就有了直觉模型。小孩子就是这么认识世界的，看到球就扔、就踢，靠探索建立心智模型。Agent 现在的问题是：任务做完了，什么都不积累。

他用的框架是强化学习里的马尔可夫决策过程：世界由状态和动作组成，手里拿着球是状态，扔出去是动作，球的落点是下一个状态。LLM 擅长直接从状态 0 跳到状态 1，因为它是下一个 token 预测器；缺的恰恰是中间那个转移函数。人类很清楚自己不知道哪个转移函数，于是好奇，于是去试。把「agent 不知道什么」量化出来，让它主动去补，好奇心就从一个玄学词变成了可解的工程问题。

这里牵出一个更大的分岔。现在的研究有两条路：递归自我改进，简称 RSI，和持续学习。两者本质都是让 agent 从经验中学习，姿势完全不同。RSI 是把模型关进黑盒，让它自己变成最强的 AI 研究员，自己改进自己，对齐风险明摆着。持续学习走的是另一条路：从与人类的交互经验中学习，把人留在回路里。

「我不想到达一个 agent 失控乱来的世界。办法就是坚持走这条对齐路径。」

团队结构也能看出他的执念。研究侧，有参与过 Gemini 3 和 Gemini Robotics 的联合创始人，有在 OpenAI 做过 GPT-4o 的，有在微软研究院搭过 Muse 基础设施的。产品侧，有在 Stripe 做支付 SDK 的，还有 Netflix 最年轻的设计工程师。

更少见的是，他们把训练代码库也产品化了：微服务、Kubernetes，训练器和 rollout 引擎全部自动扩缩容。设计工程师会真的去跑训练，理解研究者的体感。至于写代码，团队大部分时间花在白板上争论系统设计，实现交给一排编码 agent 组成的软件工厂。

再往后推，产品经理这个职业会变成园丁。产品自己会长，你的工作是插好架子，把品味灌进去。把产品扔给几百个用户，它自己生长。

从狩猎采集到分工社会

主持人最后请 Ronak 描绘最乐观的未来，他搬出了亚当·斯密。《国富论》写的是 18 世纪：人人都是工匠，端到端干完整条流程。斯密的理论是，丰裕的世界需要分工，让每个人别来回切换上下文，专注在自己积累了经验的事情上。

他的判断是，AI 现在还停在前工业时代，甚至狩猎采集社会：所有人排着队，咨询同一个技术神谕。要走向丰裕，就得走向分工，让每家公司都能定制模型和 harness 的每个部分。

还有一个常被忽略的事实：Google、Amazon、Facebook 这些上一代巨头，其实早就做过持续学习。推荐系统和广告，从真实世界的偏好里学习，越用越聪明。Agent 到今天还没有这套东西。Ronak 的愿景，是把 Trajectory 最终变成一个巨大的推荐系统，每个 agent 都对准每家公司、每个用户调校。

眼下这个市场的空隙大得惊人：只有 1% 的企业真正用上了 AI，大量工作流还是纯手工。他的目标，是把 1% 变成 99%。

主持人有个总结挺漂亮：基础模型实验室给了世界过剩的智能，各行各业的人每天在积累大量经验，两者之间隔着一条鸿沟。持续学习就是填沟的东西，它让那些辛苦挣来的经验，变得能被智能读懂。当然，这事一家公司干不完，Trajectory 办公室两条街外有做沙箱的 Modal，再两条街是 Thinking Machines，整套基础设施都得有人建。

说点马上能做的，听完这期就能动手。

  • 开始记录完整轨迹。主 agent、子 agent、用户反馈，尽量合成一条时间线。用 LangChain、Braintrust、Raindrop 或者自建都行，先把数据攒起来。没有轨迹，后面一切免谈。
  • 写下你的「好是什么样子」。挑 50 到 100 条有代表性的 trace，写清评分标准。这件事不花算力，今天就能做，它比换任何模型都值钱。
  • 审一遍你的 harness。数一数有多少任务真的需要前沿模型，标出那 10%，剩下的想清楚能不能路由给更小更便宜的模型。省下来的真金白银，比多调几轮提示词多得多。
  • 学 Trajectory 的团队用法：把时间花在白板和系统设计上，实现交给编码 agent。人该干的事是判断「好是什么样子」，这件事 agent 替代不了。
